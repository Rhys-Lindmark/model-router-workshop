The idea

Expensive but right, or cheap but wrong?

Always the small model

65.5% right

$0.51 per 1,000 prompts

Always the large model

94.6% right

$11.08 per 1,000 prompts: 22× the price

Pick per prompt, perfectly

97.0% right

$1.70: the cheapest model that gets each one right

A model router looks at each prompt and picks the cheapest model that will get it right. The hard part: you have to decide before you know the answer.

Meet Jev

A judgment model, not a decision model.

Jev is a classifier you program in English. You give it some text and a typed question. It gives back a calibrated probability: 0.9 means right about 9 times in 10.

Noul · yes or no

"Does a correct answer depend on exact digits?"

→ 0.99

Score · a scale

"How much working out does a good answer take?"

→ none .01 · few .46 · plan .38 · long .15

Choice · one of N

"Which model should I use?"

→ Haiku .18 · Sonnet .32 · Opus .46

Small and cheap: about 4 cents per thousand prompts. One request can ask many questions.

Real answers from the eval · Jev by TypeSafe · $0.042 per million input tokens, output free6
Tie this back to the poll. A classifier puts text in buckets. Jev lets you write the buckets as questions. The key word is judgment: Jev is good at “what is this text like?” It is not meant to make your business decisions. Keep that distinction in mind, because the first router I wrote ignored it.
LEVEL 1 · I DOAsk for the decision

My first router: one question.

// the question: starter/choice.js
model_choice: {
  type: 'choice',
  instructions:
    'Which model should I use for this prompt?',
  criteria: {
    Haiku: 'Claude Haiku', Sonnet: 'Claude Sonnet',
    Opus: 'Claude Opus',   Fable: 'Claude Fable'
  }
}

// the code
route = argmax(probabilities)
// Jev’s answer for “Compare a Roth IRA and a
// traditional 401(k) for someone earning $90k”
"model_choice": {
  "choice": "Sonnet",
  "probabilities": {
    "Haiku":  0.11,
    "Sonnet": 0.72,                  ← top
    "Opus":   0.16,
    "Fable":  0.01
  }
}
// route → Sonnet. Effort? Why? No answer.

LEVEL 1 · I DOGood or bad?

It works. It’s also a decision dressed up as a question.

  • Good: one call, one line, and it gives sensible-looking picks.
  • The options are just labels. “Opus” says nothing about the prompt. The answer depends on what Jev happens to know about Opus.
  • Your policy hides in the model. Cost vs quality is your call. Here it lives in Jev’s weights, not in code you can read.
  • It fails the human test. Ask a smart colleague this question and they’d say, “Do you care about cost or quality?”
  • Nothing to change but the wording. No rows, no thresholds, no “why”.
The human test: could a smart person answer it from the prompt alone?8
Reveal one at a time, ideally after someone in the room has said it. The human test is the one to repeat: if a smart person couldn’t answer the question from the prompt alone, without asking what you care about, Jev can’t either. It just guesses confidently. We’ll see in the eval how much that costs.

LEVEL 2 · I DOJudgments + a table

Ask what a smart person could judge. Decide in code.

Prompt

“Compare a Roth IRA and a traditional 401(k) for someone earning $90k”

→

Jev judges

How much working out? Specialist expertise? High stakes? Large output? Nuanced writing?

→

Code decides

A truth table: ordered rows, first match wins. You can read it, test it, diff it.

// my first five judgments: src/questions.js
reasoning_depth: { type: 'score', instructions: 'How much working out does a good answer to `prompt` take?' },
expertise:       { type: 'noul',  instructions: 'Does answering `prompt` well take specialist expertise?' },
high_stakes:     { type: 'noul',  instructions: 'Could a wrong answer to `prompt` cause real harm or cost?' }, …

Do these pass the human test? (Yes: you can answer each from the prompt alone.)

No model names, no prices: just facts about the prompt11
Decomposition is the skill. Instead of “which model?”, ask the questions you’d ask yourself before deciding. None of them mentions a model or a price. Then code turns them into a decision. Click: ask whether they pass the human test. They do. Next slide: what it did with the Roth IRA prompt.
LEVEL 2 · I DOWhat it did

Roth IRA vs 401(k) → Opus, high effort.

// Jev judges: one request, five answers
reasoning_depth  none .00  few .00
                 plan 1.00  long .00   → plan
expertise        0.40               → unsure
high_stakes      0.92               → yes
large_output     0.10               → no
nuanced_writing  0.16               → no

// how my code reads a yes/no answer
yes ≥ 0.7 · no ≤ 0.3
UNSURE_COUNTS_AS = true      ← so expertise = yes
// code decides · src/policy.js
// effort, from (depth, high stakes)
{ depth: 'plan', stakes: false, level: 'Medium' },
{ depth: 'plan', stakes: true,  level: 'High' }, ← match

// model: first match wins
{ test: j => j.large_output,               tier: 'fable' },
{ test: j => j.depth === 3,                tier: 'fable' },
{ test: j => j.expertise && j.depth >= 2,  tier: 'opus' }, ← match
{ test: j => j.expertise && j.high_stakes, tier: 'opus' },
{ test: j => j.expertise,                  tier: 'sonnet' },
  … 3 more rows, ending in
{ test: () => true,                        tier: 'haiku' },

LEVEL 3 · I DOCheck it with an eval

Run every model on every prompt. Grade by code.

228

prompts: math, code, writing, logic, facts. Every answer checked by code. No LLM judge.

6

options per prompt: three model sizes × low and high effort. Now any router is a lookup.

60 / 168

train / test. Build from the 60. Score only on the 168.

Compare every router to fixed choices, perfect routing and random routing with the same mix of picks. Cost of the whole run: $15.

Without baselines, every router looks good14
This is how you answer “was Opus the right call?”. Run every option on every prompt once, grade by code, and then any routing policy can be scored for free by lookup. The random baseline deals the same picks to prompts at random 10,000 times. If your router can’t beat that, it isn’t routing; it’s a price mix.

LEVEL 3 · I DOWhat the eval taught me

The failures weren’t expertise or stakes. They were exact details and long procedures.

// Router v2 asks four new questions,
// with Jev’s answers on the Roth IRA prompt
exact_details           0.08  no
  exact letters, words or digits?
long_procedure          0.11  no
  a long step-by-step procedure?
quick_recall            0.06  no
  one well-known fact or one step?
writes_code             0.02  no
  asks for code?
// src/policy.js · ROUTER_V2 · first match wins
1  j.exact_details && j.long_procedure                   sonnet:high
2  j.exact_details && (j.quick_recall || j.depth === 0)  haiku:high
3  j.exact_details                                       sonnet:high
4  j.long_procedure                                      sonnet:high
5  j.large_output                                        opus:low
6  j.writes_code                                         haiku:high
7  j.quick_recall                                        haiku:low
8  otherwise                                             sonnet:low ←

Remember the quiz? 91.1% at $3.20, vs “which model?” at 85.7% for $7.37. The Roth IRA prompt now goes to Sonnet at low effort: nothing exact, nothing long.

Written from the 60 training prompts only · the best re-tune of v1’s thresholds reached 87.5%16
The fix was better questions, not better thresholds. When I tried re-tuning v1, the best I got was 87.5% at much higher cost. And one honest note: on this prompt set, always using the medium model at high effort scores 93.5% at $3.32, as good as my best router. You only learn that by running the eval. A router earns its keep when you don’t know the right fixed choice in advance, or when your traffic changes.
